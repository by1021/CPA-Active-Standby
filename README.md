## 可运行服务

[CPA DR 部署与使用说明](cpa-dr/README.md) · [本地验收记录](cpa-dr/docs/verification.md)

在两台服务器分别执行，`TARGET` 替换为已存在的 CPA 数据父目录：

```bash
cd cpa-dr
bash start.sh --data-dir TARGET
```

缺少宿主依赖时，脚本列出缺失项并询问 `[y/N]`，确认后安装、复检并继续；非 root 通过 sudo 安装。无人值守可加 `--yes`，只检查不安装可加 `--no-install-deps`；软件源、支持的包管理器和 Docker 权限说明见服务 README。

服务使用 Bash、rsync、tar、jq、OpenSSH 和 sqlite3 原生命令，无 Python 后端。登录中文控制台，设置主／备角色、数据标签与路径、备份周期及对端 SSH 地址；交换公钥、核对主机指纹后启用定时任务。默认管理地址仅绑定 `127.0.0.1:8787`；远程管理和跨机连接见服务说明。旧脚本与本服务选择一种调度方式，不同时对同一数据执行接管或恢复。

## 核心规则

```text
主站正常：主 → 备，备机保留历史快照。
备站接管：停止主 → 备，以备站数据为准。
主站恢复：仍由备站服务，先备 → 主，校验完成再回切。
回切完成：恢复主 → 备。
```

- 建议同步每 2 分钟一次；备机本地快照每小时一次，保留 7 天。它们是初始方案参数，不是已经运行的定时任务。
- 日常采集不停止服务节点；恢复目标可能自动重启，故障切换及最终回切可能有短暂中断。
- 角色不明确、备份损坏或传输失败时，停止覆盖并告警，不猜测数据来源。
- 实际容器名、数据挂载、版本、数据库和 OAuth 刷新行为以两台服务器核对结果为准。
