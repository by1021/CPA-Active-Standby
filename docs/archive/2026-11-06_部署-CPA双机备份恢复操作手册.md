# CPA 双机备份与恢复：逐步操作手册

> 日期：2026-11-06。依据：`2026-11-05_部署-CPA双机主备-report.md`。
> 当前状态按你的反馈：主备服务器及统一入口已经配置，故障时可以切到备站；本文不重复部署 Worker、KV、域名或隧道。
> **执行方式：先做第 1～7 节，落地自动备份；第 8～10 节只在演练、故障或恢复时执行。**

## 0. 先明确这次会得到什么

本手册按“**保留现有请求切换；备份自动执行；恢复和回灌人工确认**”编排。原报告中的完整自动接管、自动回灌、启动保护属于更进一步的数据自动化，本文不把定时复制冒充这些能力。

| 项目 | 执行本手册后 |
|---|---|
| 主站在线备份 | 每 2 分钟尝试生成一个经过校验的副本，不停止 CPA |
| 主站数据保存在备机 | 备机每 2 分钟拉取主站已完成副本，放进独立备份目录 |
| 历史版本 | 两端各保留最近两份，以及最近 7 天内每个 UTC 小时的最新成功版本 |
| 备站接管后的新数据 | 备站自己的本地快照一直开启，不依赖人工切换后才开始备份 |
| 防止旧主覆盖新备 | 主站来源与备站来源分目录；备份脚本不写任何 CPA 运行目录 |
| 回灌、历史恢复 | 暂存、校验、保留目标原数据、人工确认后应用 |
| 自动更新备站运行凭据 | **未实现**；收到备份不等于备站 CPA 已加载它 |
| 无人值守回灌、严格单写、重启后自动隔离 | **未实现**；第 11 节列出完整报告的剩余前置条件 |

**操作前的三个重点：**

1. 两个常驻 CPA 可能各自刷新 OAuth 凭据。备份成功只证明文件副本有效，不证明上游 token 仍有效；不要设双向 `rsync --delete` 定时覆盖认证目录。[1][5]
2. 本文不修改现有 Worker。现有 `auto` 模式会在主站探测恢复时自动回主；故障后的旧主必须先隔离，再回灌。单改 KV 有传播延迟，不能替代源站隔离。[2][3]
3. 下文的 `/var/lib/cpa-backup`、`/etc/cpa-backup.json`、两个 `/usr/local/sbin/cpa-*` 是**本手册新建路径**；CPA 原目录一律从实际挂载读取，不假设它位于 `/root/cpa`。[4]

### 0.1 两台机器怎么称呼

| 代号 | 含义 | 在哪里操作 |
|---|---|---|
| A / 主机 / `primary` | 正常情况下提供服务的主服务器 | 主机 SSH 终端 |
| B / 备机 / `backup` | 故障时接管的备用服务器 | 备机 SSH 终端 |
| 控制台 | 已有 Cloudflare 账号 | 浏览器，不是 Linux 命令行 |
| `HOST` / `PORT` | 按步骤输入的实际 SSH 地址和端口 | 不要把 API 域名当 SSH 地址 |
| `TOKEN` | 测试时临时输入的 CPA 调用密钥 | 不写进脚本、仓库或备份日志 |

适用命令环境：**Debian / Ubuntu、Bash、systemd、Docker，具有 root 管理权限**。其他发行版先换成对应的包管理命令；容器名、挂载、数据库、存储空间及 SSH 通道均需现场核对。

命令按小节逐块执行，不把整篇一次性粘贴进终端。代码中的 `set -e` 表示遇到非预期错误就停止当前 shell；处理错误、重新登录后，从该小节复核再继续。断线后需要重新读取该节变量，不沿用空的 `BATCH` / `AUTH_DIR`。

### 0.2 哪些东西备份，哪些不自动覆盖

| 内容 | 是否备份 | 恢复方式 |
|---|---|---|
| 认证目录及目录下全部普通文件 | 是，包含 SHA256 清单 | 服务停止后，按选定权威版本单向恢复 |
| CPA 配置 | 是 | 合并调用密钥、模型等共享配置；保留本机代理和路径 |
| Compose 文件、镜像引用及镜像 ID、挂载信息 | 是 | 作为部署依据，不拉取 `latest`，不直接覆盖另一台的 Compose |
| `.env`、override、证书等额外文件 | 在第 2 节逐个加入 `extra_files` | 按记录的原路径、本机差异恢复 |
| 运行中的数据库 | 不直接纳入此文件复制任务 | 先做对应数据库的一致性导出，再将导出文件加入 `extra_files` |
| 日志 | 默认不纳入 | 单独设置保留策略 |
| cloudflared 隧道凭据、服务器私钥 | 不做跨机应用 | 每机独立保管，恢复时保留本机值 |

如果使用远程数据库、Redis、对象存储或其他 CPA 分支的数据后端，先补齐该后端的导出/恢复步骤。文件复制不覆盖这部分状态。本文脚本校验普通 JSON/YAML 语法，不等于数据库一致性或 CPA 配置语义校验。[1][4][5]

重点看 `Mounts` 的 `Source`（宿主机路径）和 `Destination`（容器内路径）。认证目录可能对应 `/root/.cli-proxy-api`，但必须同时核对本机 CPA 配置的 `auth-dir`。[5]

| 要记录的信息 | A | B |
|---|---|---|
| 容器名 | 现场记录 | 现场记录 |
| 认证目录的宿主机绝对路径 | 现场记录 | 现场记录 |
| 配置文件的宿主机绝对路径 | 现场记录 | 现场记录 |
| 实际启动使用的 Compose 文件 | 现场记录 | 现场记录 |
| `.env`、override、证书、数据库导出等依赖 | 现场记录 | 现场记录 |
| 镜像 ID / 版本 / 原重启策略 | 现场记录 | 现场记录 |

核对要求：

- 文件在宿主机可读，不是只存在容器可写层中；否则先规划持久化，别把空目录当备份来源。
- 如果认证存储是 Docker named volume，先用 `docker volume inspect` 确认实际 Mountpoint，文件系统和驱动需支持本机读取；远程卷需对应存储的备份方法。[4]
- 两机时钟已同步；副本新鲜度检查允许最多 60 秒的未来时钟偏差。
- 原始数据最好不超过几百 MB，先测量实际用时。脚本超时为轻量认证文件设置，大数据量需调整。
- 一份副本大小记为 S：备机最多约保存主来源 170 份和备来源 170 份，另加暂存与手工保留副本。按 **340 × S + 余量**估算备机容量，压缩/去重不在本文实现中。

下面交互创建本机配置；A 输入 `primary`，B 输入 `backup`。额外文件逐个输入绝对路径，最后直接回车结束。

```bash
set -e
/usr/bin/python3 - <<'PY'
import json, os
from pathlib import Path
os.umask(0o077)
output = Path('/etc/cpa-backup.json')
if output.exists():
    raise SystemExit('配置已存在；请编辑现有文件，不覆盖原参数')
with open('/dev/tty', 'r+') as tty:
    def ask(prompt):
        tty.write(prompt); tty.flush()
        return tty.readline().strip()
    node = ask('本机角色名称，primary 或 backup: ')
    assert node in ('primary', 'backup')
    c = {'node': node, 'container': ask('本机 CPA 容器名: '),
         'backup_root': '/var/lib/cpa-backup', 'min_auth_json': 1}
    for key, label in [('auth_dir', '认证目录'), ('config_file', 'CPA 配置文件'),
                       ('compose_file', '实际 Compose 文件')]:
        p = Path(ask(label + '的宿主机绝对路径: '))
        assert p.is_absolute() and p.exists() and not p.is_symlink()
        assert p.is_dir() if key == 'auth_dir' else p.is_file()
        c[key] = str(p)
    c['extra_files'] = []
    while True:
        value = ask('额外文件绝对路径，直接回车结束: ')
        if not value: break
        p = Path(value)
        assert p.is_absolute() and p.is_file() and not p.is_symlink()
        c['extra_files'].append(str(p))
output.write_text(json.dumps(c, ensure_ascii=False, indent=2) + '\n')
output.chmod(0o600)
print('已写入 /etc/cpa-backup.json')
PY
```

默认要求至少 1 个认证 JSON。若本机确实只用配置内的 API Key、认证目录为空，人工核对后将 `min_auth_json` 改为 `0`；不要为了绕过异常把空目录检查关掉。

> 本机配置的 `node` 表示**物理来源身份**，后续接管也不改它。B 接管后仍是 `backup` 来源。

## 3. 两台安装本地快照脚本

**执行位置：A、B。整块复制一次，再执行下一节。**

脚本会：采集前后分别做源文件校验 → 校验暂存副本 → 记录部署信息 → 发布完整快照 → 更新 `LATEST` → 按完成时间保留历史。失败不把半成品发布为最新副本。认证源目录和备份目录分离；在线采集仍不是跨文件事务快照。[1][5]

<summary>展开：完整 cpa-snapshot 安装命令（整块复制）</summary>

```bash
set -e
cat > /usr/local/sbin/cpa-snapshot <<'CPA_SCRIPT'
#!/usr/bin/python3
import datetime as dt
import fcntl
import hashlib
import json
import os
from pathlib import Path
import re
import shutil
import stat
import subprocess as sp
import sys
import tempfile
import time
import uuid
import yaml

os.umask(0o077)
PATTERN = re.compile(r"[0-9]{8}T[0-9]{6}Z-[0-9a-f]{8}")

def require(ok, message):
    if not ok:
        raise RuntimeError(message)

def inventory(root):
    require(root.is_dir() and not root.is_symlink(), "目录缺失或为符号链接")
    result = {}
    for p in sorted(root.rglob("*")):
        require(not p.is_symlink(), "备份范围含符号链接，请先人工核对")
        if p.is_dir():
            continue
        require(p.is_file(), "备份范围含特殊文件")
        h = hashlib.sha256()
        with p.open("rb") as f:
            for chunk in iter(lambda: f.read(1024 * 1024), b""):
                h.update(chunk)
        result[p.relative_to(root).as_posix()] = {
            "sha256": h.hexdigest(), "size": p.stat().st_size,
        }
    return result

def source_files(c):
    result = [(c["config_file"], "config.yaml"), (c["compose_file"], "compose.yaml")]
    for i, value in enumerate(c.get("extra_files", [])):
        result.append((value, f"extras/{i:03d}-{Path(value).name}"))
    return result

def source_inventory(c):
    result = {"auths/" + k: v for k, v in inventory(Path(c["auth_dir"])).items()}
    for value, name in source_files(c):
        p = Path(value)
        require(p.is_file() and not p.is_symlink(), "配置文件缺失或为符号链接")
        result[name] = {"sha256": hashlib.sha256(p.read_bytes()).hexdigest(),
                        "size": p.stat().st_size}
    return result

def validate_payload(root, minimum):
    files = list((root / "auths").rglob("*.json"))
    require(len(files) >= minimum, "认证 JSON 数量小于配置下限")
    for p in files:
        try:
            value = json.loads(p.read_text())
        except (ValueError, UnicodeError):
            raise RuntimeError("认证 JSON 校验失败；未输出敏感内容") from None
        require(isinstance(value, dict), "认证 JSON 不是对象")
    for name in ["config.yaml", "compose.yaml"]:
        try:
            value = yaml.safe_load((root / name).read_text())
        except (yaml.YAMLError, UnicodeError):
            raise RuntimeError("YAML 解析失败；未输出敏感内容") from None
        require(isinstance(value, dict), "YAML 顶层不是映射")

def verify(path):
    require(path.is_dir() and not path.is_symlink(), "快照路径无效")
    expected = json.loads((path / "manifest.json").read_text())
    actual = inventory(path)
    actual.pop("manifest.json", None)
    require(actual == expected, "快照清单或 SHA256 不一致")
    meta = json.loads((path / "meta.json").read_text())
    require(meta["node"] in ("primary", "backup"), "快照来源无效")
    require(PATTERN.fullmatch(meta["id"]) is not None, "快照编号无效")
    validate_payload(path / "payload", meta["min_auth_json"])
    return meta

def atomic_text(path, value):
    tmp = path.with_name("." + path.name + "." + uuid.uuid4().hex)
    try:
        with tmp.open("w") as f:
            f.write(value)
            f.flush()
            os.fsync(f.fileno())
        os.replace(tmp, path)
    finally:
        tmp.unlink(missing_ok=True)

def prune(store):
    latest = (store / "LATEST").read_text().strip()
    require(PATTERN.fullmatch(latest) is not None, "LATEST 无效")
    verify(store / latest)  # 最新副本损坏时不清理任何版本。
    versions = []
    for p in store.iterdir():
        if PATTERN.fullmatch(p.name) and p.is_dir() and not p.is_symlink():
            meta = json.loads((p / "meta.json").read_text())
            versions.append((float(meta["completed_epoch"]), p))
    versions.sort(key=lambda v: v[0], reverse=True)
    keep = {latest} | {p.name for _, p in versions[:2]}
    hours = set()
    for epoch, p in versions:
        bucket = int(epoch // 3600)
        if epoch >= time.time() - 7 * 86400 and bucket not in hours:
            keep.add(p.name)
            hours.add(bucket)
    for _, p in versions:
        if p.name not in keep:
            shutil.rmtree(p)

def create(c):
    require(c["node"] in ("primary", "backup"), "node 应为 primary 或 backup")
    root = Path(c["backup_root"]).resolve()
    auth = Path(c["auth_dir"]).resolve()
    require(auth != Path("/") and auth not in root.parents and root not in auth.parents
            and auth != root, "认证目录与备份目录重叠")
    store = root / "export"
    store.mkdir(parents=True, exist_ok=True, mode=0o700)
    with (root / "snapshot.lock").open("a") as lock:
        fcntl.flock(lock, fcntl.LOCK_EX)
        before = source_inventory(c)
        require(shutil.disk_usage(root).free > sum(x["size"] for x in before.values()) * 3
                + 64 * 1024 * 1024, "备份磁盘可用空间不足")
        stage = Path(tempfile.mkdtemp(prefix=".stage-", dir=store))
        try:
            payload = stage / "payload"
            (payload / "auths").mkdir(parents=True)
            pairs = [(str(auth) + "/", str(payload / "auths") + "/")]
            for source, name in source_files(c):
                (payload / name).parent.mkdir(parents=True, exist_ok=True)
                pairs.append((source, str(payload / name)))
            for source, target in pairs:
                sp.run(["rsync", "-a", "--numeric-ids", "--", source, target],
                       check=True, timeout=90, stdout=sp.DEVNULL)
            require(before == source_inventory(c) == inventory(payload),
                    "采集期间源数据变化；本轮不发布，等下一轮重试")
            validate_payload(payload, c["min_auth_json"])
            template = ('{"image_ref":{{json .Config.Image}},"image_id":{{json .Image}},'
                        '"mounts":{{json .Mounts}}}')
            info = json.loads(sp.check_output(
                ["docker", "inspect", "--format", template, c["container"]], timeout=15))
            now = time.time()
            batch = dt.datetime.fromtimestamp(now, dt.timezone.utc).strftime("%Y%m%dT%H%M%SZ")
            batch += "-" + uuid.uuid4().hex[:8]
            meta = {"id": batch, "node": c["node"], "completed_epoch": now,
                    "min_auth_json": c["min_auth_json"], "deployment": info,
                    "source_paths": {k: c[k] for k in ("auth_dir", "config_file", "compose_file")},
                    "extra_files": c.get("extra_files", [])}
            (stage / "meta.json").write_text(json.dumps(meta, indent=2) + "\n")
            (stage / "manifest.json").write_text(json.dumps(inventory(stage), indent=2) + "\n")
            verify(stage)
            # 先刷盘，再发布目录及指针；进程中断不把暂存目录当成有效快照。
            os.sync()
            os.rename(stage, store / batch)
            atomic_text(store / "LATEST", batch + "\n")
            os.sync()
            prune(store)
            atomic_text(root / "snapshot.failures", "0\n")
            print(batch)
        finally:
            if stage.exists():
                shutil.rmtree(stage)

def main():
    action = sys.argv[1]
    if action == "verify":
        print(json.dumps(verify(Path(sys.argv[2])), ensure_ascii=False))
    elif action == "prune":
        prune(Path(sys.argv[2]))
    elif action == "create":
        config = Path(os.environ.get("CPA_BACKUP_CONFIG", "/etc/cpa-backup.json"))
        c = json.loads(config.read_text())
        try:
            create(c)
        except Exception:
            root = Path(c["backup_root"])
            if root.is_dir():
                counter = root / "snapshot.failures"
                try:
                    n = int(counter.read_text()) + 1
                except (OSError, ValueError):
                    n = 1
                atomic_text(counter, str(n) + "\n")
                print(f"{'ALERT' if n >= 3 else 'ERROR'}: 连续快照失败 {n} 轮", file=sys.stderr)
            raise
    else:
        raise RuntimeError("用法：cpa-snapshot create | verify 快照目录 | prune 存储目录")

if __name__ == "__main__":
    try:
        main()
    except Exception as e:
        # 标准库/解析器异常可能带出敏感内容，只显示异常类型。
        print(str(e) if isinstance(e, RuntimeError) else type(e).__name__, file=sys.stderr)
        sys.exit(1)
CPA_SCRIPT
chmod 700 /usr/local/sbin/cpa-snapshot
```

## 4. 建立 B 读取 A 的专用 SSH 通道

这里是**备机拉取主机备份**，数据方向仍为 A → B。专用密钥只允许读取 A 的导出目录，不允许写入或进入交互 shell。[7][8]

### 4.1 B 生成备份专用密钥

```bash
set -e
install -d -m 700 /root/.ssh
test -f /root/.ssh/cpa_backup_ed25519 || \
  ssh-keygen -t ed25519 -N '' -f /root/.ssh/cpa_backup_ed25519 -C cpa-backup-readonly
cat /root/.ssh/cpa_backup_ed25519.pub
```

复制输出的**公钥一行**，私钥只留在 B。

### 4.2 A 添加受限公钥，并记录主机指纹

```bash
set -e
RRSYNC=$(command -v rrsync)
test -x "$RRSYNC"
install -d -m 700 /root/.ssh
touch /root/.ssh/authorized_keys
chmod 600 /root/.ssh/authorized_keys
read -rp '粘贴 B 的备份公钥完整一行: ' PUBLIC_KEY
[[ "$PUBLIC_KEY" == ssh-ed25519\ * ]]
printf 'restrict,command="%s -ro /var/lib/cpa-backup/export" %s\n' \
  "$RRSYNC" "$PUBLIC_KEY" >> /root/.ssh/authorized_keys
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
```

把最后一行的 `SHA256:...` 主机指纹，通过当前可信管理通道记录下来。若服务器禁止 root 公钥登录，改用已批准的专用账号与只读目录权限方案，先验证权限后再启用任务；不要直接放宽整个 SSH 服务配置。

### 4.3 B 核对主机指纹，再保存专用连接配置

以下适用于 B 可直接 SSH 连接 A 的情况。已有跳板、VPN、SSH Access 通道时，在专用配置中加入原来可用的 `ProxyJump` / `ProxyCommand`，不要另猜网络地址。

```bash
set -e
read -rp 'A 的可达 SSH 地址: ' HOST
read -rp 'A 的 SSH 端口: ' PORT
[[ "$PORT" =~ ^[0-9]+$ ]]
CANDIDATE=$(mktemp)
ssh-keyscan -T 10 -t ed25519 -p "$PORT" "$HOST" > "$CANDIDATE"
test -s "$CANDIDATE"
ssh-keygen -lf "$CANDIDATE"

Host cpa-backup-source
    HostName $HOST
    Port $PORT
    User root
    IdentityFile /root/.ssh/cpa_backup_ed25519
    IdentitiesOnly yes
    UserKnownHostsFile /root/.ssh/cpa_backup_known_hosts
    StrictHostKeyChecking yes
    BatchMode yes
    ConnectTimeout 10
    ServerAliveInterval 15
    ServerAliveCountMax 2
EOF
chmod 600 /root/.ssh/cpa_backup_config
rsync -a --timeout=30 -e 'ssh -F /root/.ssh/cpa_backup_config' -- \
  cpa-backup-source:LATEST /var/lib/cpa-backup/ssh-test-LATEST
cat /var/lib/cpa-backup/ssh-test-LATEST
```

预期：能读到 A 刚刚生成的快照编号。使用这个密钥执行普通 `ssh ... true` 被拒绝是预期行为，不需要取消 `rrsync` 限制。

## 5. 只在 B 安装接收脚本

脚本只接收主站已校验的不可变批次，先暂存再校验；源快照超过 10 分钟不发布。`role` 是**人工控制的本地备份开关**，不是 Worker 的实时角色、分布式锁或自动故障探测器。

### 5.1 设置当前来源开关

在已有统一入口确认当前流量来源，主站服务时输入 `primary`；备站已接管则输入 `backup`；不明确时输入 `paused`。

```bash
set -e
read -rp '当前权威节点 primary / backup；不确定填 paused: ' ROLE
case "$ROLE" in primary|backup|paused) ;; *) exit 1 ;; esac
test ! -e /var/lib/cpa-backup/role
printf '%s:%s\n' "$ROLE" "$(date -u +%Y%m%dT%H%M%SZ)" > /var/lib/cpa-backup/role
chmod 600 /var/lib/cpa-backup/role
```

### 5.2 安装脚本

```bash

  primary:*) ;;

  /usr/local/sbin/cpa-snapshot verify "$STORE/$BATCH" >/dev/null
else
  sync
  mv -- "$STAGE/batch" "$STORE/$BATCH"
fi
# role 的人工修改也使用同一个 pull.lock；确认修改返回后，旧任务已结束。
printf '%s\n' "$BATCH" > "$STORE/.LATEST.new"

mv -f -- "$STORE/.LATEST.new" "$STORE/LATEST"
sync
/usr/local/sbin/cpa-snapshot prune "$STORE"
date -u +%FT%TZ > "$ROOT/pull.last-success"
printf '0\n' > "$ROOT/pull.failures"
```

### 5.3 手工试跑

主站当前服务、`role=primary:...` 时，在 B 执行：

```bash
set -e
/usr/local/sbin/cpa-pull
BATCH=$(cat /var/lib/cpa-backup/received/primary/LATEST)
/usr/local/sbin/cpa-snapshot verify "/var/lib/cpa-backup/received/primary/$BATCH"
```

预期：输出 `OK: 已接收并校验 ...`，来源为 `primary`。若当前为 `backup` / `paused`，输出 `SKIP` 是预期的保护动作，不要为了让试跑通过而改错角色。

### 5.4 三个位置不要混用

| 位置 | 保存什么 | 是否自动应用给 CPA |
|---|---|---|
| A 的 `/var/lib/cpa-backup/export` | A 自己的数据版本 | 否 |
| B 的 `/var/lib/cpa-backup/received/primary` | 从 A 收到的数据版本 | 否 |
| B 的 `/var/lib/cpa-backup/export` | B 自己的数据版本，包含接管后的变化 | 否 |
| 任一机的 `/var/lib/cpa-backup/pinned` | 人工固定、覆盖前保留的版本 | 否，也不自动清理 |

正常时要恢复主站数据，选择 B 的 `received/primary`；备站接管后要回灌主站，选择 B 的 `export`。**不要因为文件时间更新就把待机自行刷新的凭据当成权威版本。**

## 6. 启用 systemd 定时任务

### 6.1 A、B 都启用本地快照

```bash
set -e
cat > /etc/systemd/system/cpa-snapshot.service <<'EOF'
[Unit]
Description=CPA validated local snapshot
After=docker.service

[Service]
Type=oneshot
User=root
UMask=0077
ExecStart=/usr/local/sbin/cpa-snapshot create
TimeoutStartSec=110
EOF

cat > /etc/systemd/system/cpa-snapshot.timer <<'EOF'
[Unit]
Description=CPA local snapshot every two minutes

[Timer]
OnCalendar=*-*-* *:0/2:00
RandomizedDelaySec=5
AccuracySec=1s
Persistent=true

[Install]

EOF

systemd-analyze verify /etc/systemd/system/cpa-snapshot.service /etc/systemd/system/cpa-snapshot.timer
systemctl daemon-reload
systemctl enable --now cpa-snapshot.timer
systemctl start cpa-snapshot.service
systemctl list-timers --all 'cpa-*'
journalctl -u cpa-snapshot.service -n 20 --no-pager
```

### 6.2 只在 B 启用主站副本拉取

```bash
set -e
cat > /etc/systemd/system/cpa-pull.service <<'EOF'
[Unit]
Description=CPA receive validated primary snapshot
Wants=network-online.target
After=network-online.target

[Service]
Type=oneshot
User=root
UMask=0077

cat > /etc/systemd/system/cpa-pull.timer <<'EOF'
```

`Persistent=true` 会在恢复计时器时补触发错过的任务，不是把离线期间每一轮全部补跑；同一 service 未完成时不会启动第二个相同实例。脚本锁额外防止手工运行重入。[6]

**2 分钟是调度间隔，不是零丢失承诺。** A 采集与 B 拉取异步，实际最新副本可能落后数分钟；持续写入、任务超时和故障会继续增加延迟。

## 7. 日常检查：备份上线到此为止

**执行位置：B 为主，A 也检查本地快照任务。**

```bash
set -e
systemctl list-timers --all 'cpa-*'
systemctl --failed --no-pager
journalctl -u cpa-snapshot.service -u cpa-pull.service --since '24 hours ago' --no-pager
cat /var/lib/cpa-backup/role
test ! -f /var/lib/cpa-backup/pull.last-success || cat /var/lib/cpa-backup/pull.last-success
du -sh /var/lib/cpa-backup/export /var/lib/cpa-backup/received/primary
df -h /var/lib/cpa-backup
```

在 B 检查两类最新副本的真实年龄，而不是只看“timer active”：

```bash
set -e
/usr/bin/python3 - <<'PY'
import json, time
from pathlib import Path
for name in ['export', 'received/primary']:
    store = Path('/var/lib/cpa-backup') / name
    if not (store / 'LATEST').exists():
        print(name, '尚无有效副本'); continue
    batch = (store / 'LATEST').read_text().strip()
    m = json.loads((store / batch / 'meta.json').read_text())
    age = int(time.time() - m['completed_epoch'])
    print(name, m['node'], batch, '年龄秒=', age,
          '需要处理：副本过旧' if age > 600 else '新鲜度正常')
PY
```

- `role=backup` 时，主来源副本不再更新是正常现象；重点检查 B 的 `export`。
- 脚本检测到连续 3 次失败会写 `ALERT`，错误保存在 systemd journal。**日志告警已包含，短信/邮件/机器人推送需接入你已有监控，本文没有假定你配置了通知渠道。**
- 服务被超时强杀、主机离线或 timer 被禁用时，不一定执行到脚本失败计数；已有监控还应检查 `systemd failed`、最后成功时间和主机存活。
- 数据损坏、空认证目录、源文件变化、SSH 断开、磁盘不足都应先排查；不先删最后一份有效副本腾空间。
- 保留策略按**快照完成时间**，同一小时挑最新成功副本；`pinned` 不清理。生成失败或最新版本验证失败时不执行历史清理。
- 本机磁盘上的多个副本仍属于同一个故障域；B 磁盘损坏会同时失去 B 的本地历史和接收历史。若要独立灾备，应另做加密离机备份。

## 8. 故障：B 已接管时怎么操作

本节不是定时任务；由你确认故障后执行。**顺序：确认 B 服务 → 阻止旧 A 自动回流 → 停止 A 来源接收 → 固定 B 的当前版本。**

### 8.1 控制台固定流量，旧 A 保持隔离

在已有 **Workers KV → `CPA_HA_STATE` → `KV Pairs`** 中，将键 `mode` 的值改成 `backup`。使用现有手册的方法，从实际客户端反复确认响应头 `X-HA-Mode: backup` 和 `X-HA-Origin: backup`。[2]

同时在服务器/云控制台隔离旧 A：阻止其 CPA 对外提供服务，并处理其自动重启路径。网络断开不代表旧 A 停止写入；有双写迹象时先暂停覆盖并核对来源。

若 A 已经可以管理，维护期间在 **A** 执行下面操作。此处停止的是旧主 CPA，不停止 B：

```bash
set -e
read -rp '旧主 A 的 CPA 容器名: ' CPA_CONTAINER
if test ! -e /var/lib/cpa-backup/pinned/A-original-restart-policy.txt; then
  docker inspect "$CPA_CONTAINER" --format '{{.HostConfig.RestartPolicy.Name}}' \
    > /var/lib/cpa-backup/pinned/A-original-restart-policy.txt
fi
docker update --restart=no "$CPA_CONTAINER"
docker stop -t 60 "$CPA_CONTAINER"
docker inspect "$CPA_CONTAINER" --format 'running={{.State.Running}} restart={{.HostConfig.RestartPolicy.Name}}'
```

还要处理实际 Compose 中该 CPA 服务的 `restart` 设置，并暂停 1Panel、Watchtower、自建 systemd/cron 等可能重建/启动它的管理任务。`docker update` 不会修改 Compose 文件；后续重建容器可能重新套用旧策略。[3]

如果 A 暂时离线，先在云控制台保持关闭/隔离；恢复 SSH 管理后执行上述保护，**不要先恢复 CPA 或隧道业务入口**。只依赖 KV、只执行一次 `docker stop`，都不算持久化启动保护。

### 8.2 B 停止拉取旧主版本，保留本地快照

```bash
set -e
systemctl stop cpa-pull.timer cpa-pull.service
flock /var/lib/cpa-backup/pull.lock bash -c '
  printf "backup:%s\n" "$(date -u +%Y%m%dT%H%M%SZ)" > /var/lib/cpa-backup/.role.new
  mv /var/lib/cpa-backup/.role.new /var/lib/cpa-backup/role
'
systemctl is-active cpa-snapshot.timer
/usr/local/sbin/cpa-snapshot create
BATCH=$(cat /var/lib/cpa-backup/export/LATEST)
/usr/local/sbin/cpa-snapshot verify "/var/lib/cpa-backup/export/$BATCH"
cp -a "/var/lib/cpa-backup/export/$BATCH" "/var/lib/cpa-backup/pinned/takeover-$BATCH"
```

B 的本地快照 timer 保持运行，记录接管期间的新增、修改、删除。A 来源副本即使曾迟到，也只保存在 `received/primary`，不覆盖 B 的运行目录或 B 来源历史。

## 9. A 恢复后：先 B → A 回灌，再回切

**本节会有最终维护窗口。** 预传期间 B 继续服务；最后一轮要停止全部凭据写入，包括后台刷新，不只是停止业务请求。以下使用两台 CPA 停止后的最终副本，换取可操作的明确交接点。

### 9.1 先保持 A 隔离，预传一份到 A

1. 保持 KV `mode=backup`；A 继续停 CPA，重启和编排入口保持保护。
2. 在 A、B 暂停备份定时任务，避免演练命令与定时任务竞争；B 的预传快照手工生成。

```bash
set -e
# A、B 各执行；本地快照 timer 暂停，但此时 B 的 CPA 仍在服务。
systemctl stop cpa-snapshot.timer cpa-snapshot.service
```

3. B 创建并固定一份预传快照：

```bash
set -e
/usr/local/sbin/cpa-snapshot create
BATCH=$(cat /var/lib/cpa-backup/export/LATEST)
cp -a "/var/lib/cpa-backup/export/$BATCH" "/var/lib/cpa-backup/pinned/precopy-$BATCH"
```

4. B 使用**已有管理员 SSH 通道**传到 A 的新暂存目录。第 4 节的密钥只有 B 读 A 权限，不是这里的 B 写 A 管理凭据。

```bash
set -e
# 在 B 执行。TARGET 是 A 的实际管理登录项，例如你已有的 SSH Host 别名。
read -rp 'A 的管理员 SSH 登录项: ' TARGET
read -rp '管理通道 SSH 端口: ' PORT
[[ "$PORT" =~ ^[0-9]+$ ]]
[[ "$BATCH" =~ ^[0-9]{8}T[0-9]{6}Z-[0-9a-f]{8}$ ]]
ssh -p "$PORT" -o StrictHostKeyChecking=yes "$TARGET" \
  "install -d -m 700 /var/lib/cpa-backup/restore-check/$BATCH"
rsync -a --numeric-ids --timeout=90 \
  -e "ssh -p $PORT -o StrictHostKeyChecking=yes" -- \
  "/var/lib/cpa-backup/pinned/precopy-$BATCH/" \
  "$TARGET:/var/lib/cpa-backup/restore-check/$BATCH/"
```

管理员目标账号需有新建目标目录和保留文件权限的能力；主机指纹仍通过可信管理通道确认。若这条写入通道尚不存在，先用现有运维文件传输方法完成**暂存目录**传输，再校验，不把只读密钥改成全权限。

5. A 执行 `cpa-snapshot verify` 校验对应暂存目录；此时仅完成预传，不启动 A，也不回切。

### 9.2 最终交接：维护、停止写入、重做最后一份

1. 通知使用者短暂维护，KV 改为 `pause`。等待现有请求结束；检查真实客户端，不用固定等待秒数推断所有地区已生效。[2]
2. A 保持停机；在 B 停止 CPA，让业务和后台刷新一起停止：

```bash
set -e
# B 执行。docker stop 超过超时会强制结束残留请求，先安排好维护窗口。
read -rp 'B 的 CPA 容器名: ' CPA_CONTAINER
docker stop -t 60 "$CPA_CONTAINER"
docker inspect "$CPA_CONTAINER" --format '{{.State.Running}}'
```

3. 确认没有其他进程写同一认证目录。在 B 重新执行以下命令，这一份才是最终权威版本：

```bash
set -e
/usr/local/sbin/cpa-snapshot create
BATCH=$(cat /var/lib/cpa-backup/export/LATEST)
/usr/local/sbin/cpa-snapshot verify "/var/lib/cpa-backup/export/$BATCH"
cp -a "/var/lib/cpa-backup/export/$BATCH" "/var/lib/cpa-backup/pinned/final-$BATCH"
```

4. 按 9.1 的传输命令重新传输，**把源目录中的 `precopy-$BATCH` 改为 `final-$BATCH`**，目标使用这次的新编号。旧预传副本保留，不混写两次快照。
5. A 校验最终目录，确认 `meta.json` 的来源为 `backup`、时间为本次最终交接，清单覆盖 B 接管期间的新变化。

### 9.3 A 保留原数据，再应用认证目录

**以下代码有一次经过确认的 `--delete`，只对 A 的已核对认证目录执行。** 它删除的是目标中权威副本已没有的文件，目的是反映已确认的删除。A、B 此时都保持 CPA 停止。

```bash
set -e
# A 执行；使用配置中登记的宿主机认证目录。
set -e
umask 077
AUTH_DIR=$(/usr/bin/python3 -c 'import json; print(json.load(open("/etc/cpa-backup.json"))["auth_dir"])')
test -n "$AUTH_DIR" && test "$AUTH_DIR" != / && test -d "$AUTH_DIR"
read -rp '输入刚收到的最终快照编号: ' BATCH
[[ "$BATCH" =~ ^[0-9]{8}T[0-9]{6}Z-[0-9a-f]{8}$ ]]
RESTORE="/var/lib/cpa-backup/restore-check/$BATCH"
/usr/local/sbin/cpa-snapshot verify "$RESTORE"

# 原数据可能已经有损坏的 JSON，因此先做原样归档，不要求它通过业务格式校验。
/usr/bin/python3 - <<'PY'
import hashlib, json, os, tarfile, time, uuid
from pathlib import Path
os.umask(0o077)
c = json.load(open('/etc/cpa-backup.json'))
dest = Path(c['backup_root']) / 'pinned' / ('before-restore-' + time.strftime('%Y%m%dT%H%M%SZ', time.gmtime()) + '-' + uuid.uuid4().hex[:8])
dest.mkdir(mode=0o700)
files = [(c['auth_dir'], 'auths'), (c['config_file'], 'config.yaml'),
         (c['compose_file'], 'compose.yaml')]
files += [(v, f'extras/{i:03d}-{Path(v).name}') for i, v in enumerate(c.get('extra_files', []))]
archive = dest / 'original-files.tar'
with tarfile.open(archive, 'x') as tar:
    for source, name in files:
        tar.add(source, arcname=name)
(dest / 'original-paths.json').write_text(json.dumps(c, indent=2) + '\n')
h = hashlib.sha256()
with archive.open('rb') as f:
    for chunk in iter(lambda: f.read(1024 * 1024), b''):
        h.update(chunk)
(dest / 'SHA256SUMS').write_text(h.hexdigest() + '  original-files.tar\n')
with tarfile.open(archive) as tar:
    tar.getmembers()
print('原样归档保留在', dest)
PY

rsync -acni --delete -- "$RESTORE/payload/auths/" "$AUTH_DIR/"
read -rp '已核对目标路径、来源、覆盖和删除清单；输入 APPLY 才恢复: ' CONFIRM
test "$CONFIRM" = APPLY
rsync -aci --delete -- "$RESTORE/payload/auths/" "$AUTH_DIR/"
DIFF=$(mktemp)
rsync -acni --delete -- "$RESTORE/payload/auths/" "$AUTH_DIR/" > "$DIFF"
cat "$DIFF"
test ! -s "$DIFF"
rm -- "$DIFF"
```

最后检查必须无差异且退出 0。不要重命名宿主机挂载目录并以为运行容器必然切换到新目录；本文在停止容器后更新**原挂载路径内部**。[4]

覆盖前的 `original-files.tar` 是隔离保留的原样归档，可能包含损坏文件；不把它发布为有效副本，也不直接解压到运行目录。需要回滚时先在独立目录校验、检查内容和 token 有效性，再按同样的停机恢复流程应用。

本脚本按文件内容和目录树恢复，`rsync -a` 还会恢复来源权限/所有者。若两端容器运行 UID/GID 不同，先根据目标容器实际身份调整权限方案，再启动；不要盲目对配置目录全量 `chmod 777`。

**配置单独处理：** 在 A 的受限终端比较 `$RESTORE/payload/config.yaml` 和 A 原配置，合并共同的 API Key、模型等，保留 A 的代理、监听、认证目录及隧道差异。Compose 与 `extras` 默认只作恢复依据，按 `meta.json` 的原路径逐项核对。不要直接用 B 的整份配置覆盖 A。

### 9.4 验证 A，再开放入口

1. KV 继续 `pause`，B 继续停止。A 的隧道/其他入口保持隔离，先只做本机测试。
2. 检查最终认证目录、配置、权限和镜像版本。启动 A 上原容器，不执行 `docker compose pull` 或切换 `latest`：

```bash
set -e
# A 执行。
read -rp 'A 的 CPA 容器名: ' CPA_CONTAINER
docker start "$CPA_CONTAINER"
docker logs --since 5m --tail 100 "$CPA_CONTAINER"
read -rp '本机可达的 CPA 地址，包含 http:// 或 https://: ' BASE_URL
read -rsp 'CPA 调用密钥: ' TOKEN; echo
curl -fsS --max-time 20 -H "Authorization: Bearer $TOKEN" "$BASE_URL/v1/models"
unset TOKEN
```

若 CPA 仅在 Docker 网络可达，使用现有部署已经验证的同网络测试方法；不要为了测试临时开放公网端口。日志在本机查看，不上传可能包含凭据的内容。

3. 用实际客户端对 A 做一次真实模型调用和一次 SSE 流式调用。确认首段、持续输出、正常结束；只看模型列表不够。
4. 核对 B 接管期间至少一个**新增、修改、删除**样本已反映到 A；测试用非敏感文件要放在独立演练目录，不向真实认证目录注入伪凭据。
5. 验收通过后开放 A 入口，先设置 KV `primary`，从实际入口确认 `X-HA-Origin: primary`。待机 B 仍保持停止，先不要直接改 `auto`。
6. 要回到原来的双常驻方式，应先解决或明确接受第 11 节的 OAuth 待机写入边界。再次安排维护窗口、设 `pause`、停止写入，将 A 的最新权威版本按相同流程传至 B 的暂存区，保留 B 原数据后再应用。核对两机配置和权限，启动容器并验证真实调用，确认 B 的有效性后才设 `auto`。这次方向是 **A → B**，不要继续使用 B → A 的最终快照；不要在运行中覆盖 B 的认证目录。未验证待机只读机制时，即使双常驻恢复，也仍只是尽力同步，不算严格单写。

> **A 已启动/调用后又失败：** 它可能已经刷新过 OAuth token。先停止并隔离 A，保留 A 此刻的新快照，核对上游有效凭据；不要直接启动保留旧 token 的 B 来“回滚”。如果 A 从未启动、凭据也未改变，可以保持 A 隔离，重启 B 并设 `backup`，继续由 B 服务。

| 交接失败位置 | 恢复操作 |
|---|---|
| 预传失败，B 尚在服务 | A 保持隔离、KV 保持 `backup`，在 B 执行 `systemctl enable --now cpa-snapshot.timer`；主来源拉取继续停止 |
| 最终传输失败，A 从未启动 | 确认 A 没有改写凭据，重启 B、设置 `backup`，恢复 B 的本地快照 timer；下次交接重新生成最终版本 |
| A 已启动或已刷新凭据 | 先隔离 A，保留两边当前数据，确认有效 token 后再恢复服务；不盲用启动前的旧副本 |

### 9.5 恢复备份调度

只有确认 A 已重新成为权威源后，在 **B** 执行：

```bash
set -e
flock /var/lib/cpa-backup/pull.lock bash -c '
  printf "primary:%s\n" "$(date -u +%Y%m%dT%H%M%SZ)" > /var/lib/cpa-backup/.role.new
  mv /var/lib/cpa-backup/.role.new /var/lib/cpa-backup/role
'
```

在 **A、B** 各执行：

```bash
set -e
systemctl enable --now cpa-snapshot.timer
systemctl start cpa-snapshot.service
```

再在 **B** 执行：

```bash
set -e
systemctl enable --now cpa-pull.timer
systemctl start cpa-pull.service
journalctl -u cpa-pull.service -n 20 --no-pager
```

`pinned` 中的覆盖前、接管和最终快照至少保留到恢复验收完成；磁盘清理时人工确认再删，不加入自动 `find -delete`。

## 10. 从历史快照恢复与停止备份

### 10.1 先做不影响服务的历史校验演练

**执行位置：B。选择一个旧版本，不操作 CPA 运行目录。**

```bash
set -e
find /var/lib/cpa-backup/received/primary -mindepth 1 -maxdepth 1 \
  -type d -name '20*T*Z-*' -printf '%f\n' | sort
read -rp '输入要演练的历史快照编号: ' BATCH
[[ "$BATCH" =~ ^[0-9]{8}T[0-9]{6}Z-[0-9a-f]{8}$ ]]
SRC="/var/lib/cpa-backup/received/primary/$BATCH"
/usr/local/sbin/cpa-snapshot verify "$SRC"
DRILL=$(mktemp -d /var/lib/cpa-backup/restore-check/drill-XXXXXXXX)
cp -a "$SRC/." "$DRILL/"
/usr/local/sbin/cpa-snapshot verify "$DRILL"
```

这一步只证明历史副本可读、完整，不证明已恢复服务。真正恢复时按第 9 节：选对来源 → 隔离目标 → 保留目标原数据 → 停止写入 → 单向应用 → 配置合并 → 本机调用和 SSE → 开放流量。

历史认证文件可能过期、被撤销或因刷新失效；JSON/SHA256 通过也仍需验证上游，必要时重新授权。不要把主来源旧快照覆盖到已经接管并产生新数据的 B。

### 10.2 只停备份，不动服务

**A：**

```bash
set -e
systemctl disable --now cpa-snapshot.timer
systemctl stop cpa-snapshot.service
```

**B：**

```bash
set -e
systemctl disable --now cpa-snapshot.timer cpa-pull.timer
systemctl stop cpa-snapshot.service cpa-pull.service
```

不会删除任何快照，也不停止 CPA 或修改 Worker。撤销备份 SSH 密钥时，只移除 A 的 `authorized_keys` 中带 `cpa-backup-readonly` 且确认属于本任务的那一行，保留原管理密钥。

中断后可能留下 `.stage-*` 暂存目录。先停对应 timer/service，确认没有手工任务，再检查具体目录并人工清理；不要把清理目标写成整个 `/var/lib/cpa-backup`。

## 11. 与原报告逐项对照：哪些已覆盖，哪些还要单独验收

| 原报告要求 | 本手册对应 | 判定 |
|---|---|---|
| 在线复制、先暂存后校验 | 第 3～6 节 | 自动执行；线上用时/一致性待实测 |
| 主来源历史、备接管历史分开 | 第 5、8 节 | 自动采集且来源独立；角色确认人工 |
| 校验失败保留原有效版 | 两个脚本 | 有实现；实际 SSH 断连演练待做 |
| 每小时历史、保留 7 天 | `prune` | 最近两份 + 每小时最新成功版；至少留最新有效版 |
| 角色切换后旧任务失效 | 第 8 节停止任务 + 同锁更新 role | 人工切换完成后阻止旧任务继续发布；不靠 KV 当锁 |
| 自动更新待机 CPA 运行数据 | 第 9 节维护窗口应用 | 人工执行，非后台自动同步 |
| 原主重启前的启动/就绪保护 | 第 8 节应急保护 | 覆盖已进入维护状态的旧主；任意时刻无人值守重启保护待实现 |
| 自动回灌再自动回切 | 第 9 节顺序化步骤 | 人工执行，非无人值守自动恢复 |
| OAuth 待机单写 | 双常驻边界已注明 | 需按实际 CPA 版本验证待机机制，或引入接管时启动的控制器 |
| 失败告警 | 失败计数、journal、年龄检查 | 本地可查；离线/超时告警及外部通知需已有监控接入 |
| 真正恢复和业务就绪 | 第 9、10 节 | 必须由你在服务器验证 |

如果要求**完整达到原报告的全自动目标**，还需实现并演练以下一组相互配合的能力，而不是增加一个 cron：

1. 与当前流量角色一致的控制流程：记录角色批次，网络状态不明确时停止覆盖；不能只拿本地 `role` 文件当自动仲裁。
2. 启动入口统一受控：覆盖宿主机重启、Docker 重启、容器自动重启、Compose/管理面板重建；旧主在回灌完成前始终不给 Worker 返回成功探测。
3. 确认待机不会刷新/写凭据，或改为接管时启动；采用后者就需要额外接管控制器，因为现有 Worker 不会启动容器。
4. 应用数据期间目标隔离；最终增量覆盖业务写入和后台刷新；验证成功后才开放入口。
5. 模糊故障、迟到任务、失败回切和 OAuth 失效都有明确处理与真实演练证据。

这些会影响现有运行方式；第 1～7 节的备份安装不修改 Worker、CPA 重启策略，也不把两台改成冷备。第 8～9 节则明确包含故障维护时的停止和启动保护操作。

## 12. 验收清单与故障速查

### 12.1 操作后的验收清单

| 检查 | 通过条件 |
|---|---|
| 路径/版本/依赖 | 两机挂载、额外文件、数据库状态和镜像均已记录 |
| 在线采集 | 真实业务持续调用时，服务节点未因备份停止，新快照验证通过 |
| 跨机备份 | B 的 `received/primary` 有来源为 A 的副本，时间持续更新 |
| 密钥限制 | 专用密钥只读 A 的导出目录，不提供管理 shell 或写权限 |
| 故障不发布 | 测试连接失败/损坏副本，原 `LATEST` 及有效版本仍在 |
| 历史策略 | 至少跨两个小时观察版本；长保留/空间异常在演练目录验证 |
| 接管备份 | B 接管后 `export` 持续记录新数据，不被 A 来源副本覆盖 |
| 真实恢复 | 用选定历史版本恢复后，实际模型调用和 SSE 均通过 |
| 回灌数据 | B 接管期间新增、修改、确认删除的数据正确反映到 A |
| 入口顺序 | A 回灌、验证之前未接业务；最终交接和失败回滚边界清楚 |
| 通知 | 能发现连续失败、快照超过 10 分钟、timer 停止或主机离线 |

前 7 节部署成功应记作“**自动备份已上线**”；不要直接记作“完整主备数据自动恢复已验收”。

### 12.2 常见问题

| 现象 | 处理 |
|---|---|
| `Permission denied (publickey)` | 核对专用公钥、SSH 端口、登录账号和服务器现有 SSH 策略 |
| 主机指纹不匹配 | 通过可信管理通道核对是否重装或改地址；不使用 `StrictHostKeyChecking=no` |
| `rrsync` 拒绝命令 | 确认只使用 rsync，远端路径相对导出根目录；不要取消只读限制 |
| 采集期间源数据变化 | 本轮不发布；持续多轮发生时查刷新频率，评估应用级导出或维护快照 |
| JSON/YAML 解析失败 | 本机检查真实文件完整性和格式；不打印认证内容到共享日志 |
| YAML 使用特殊 Compose 标签 | 普通 PyYAML 校验不支持的标签需适配解析器并重测，不关闭全部校验 |
| 源副本落后超过 10 分钟 | 先查 A 的采集 timer、服务失败、磁盘和两机时间，再查传输 |
| `SKIP` | 检查 B 的本地 `role`，与当前权威来源一致就属于正常保护 |
| timer active 但没新副本 | 查看 service 的退出码、日志、LATEST 年龄；active 只表示 timer 存在 |
| 空间不足 | 保留有效版，先扩容或人工核对可删除历史/pinned/残留暂存；不盲删 |
| 恢复后列表正常但调用失败 | 核对出站网络、代理、模型和 OAuth 有效性，必要时重新授权 |

同一路径连续失败 3 次，保留具体 stderr、发生时间、快照编号和已尝试步骤再排查；不要反复重跑覆盖命令。
