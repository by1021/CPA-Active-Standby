# 恢复历史数据

在**需要写入数据的目标节点**执行。历史恢复不是故障接管，不自动让待机节点成为权威，不启动 CPA 或切换 Cloudflare。

1. 停止目标 CPA 全部写入，包括在途请求、后台刷新和自动重启。
2. 「备份历史」选择快照，先校验。
3. 「预览 / 恢复」检查标签映射、目标路径、新增/修改/删除和权限。
4. 核对真实数据与快照，勾选停写确认，输入 `RESTORE`。
5. 等待作业最终成功，确认目标数据通过校验。
6. 核对唯一权威节点，再人工启动/验证 CPA，按业务流程开放入口。

恢复反映新增、修改与删除。写入前保留覆盖前回滚，原位恢复保留本机 inode/所有权。目标普通文件硬链接、符号链接及状态/数据交集等异常在预览和实写阶段拒绝。

## 权限与驱动

恢复要求数据可写；普通备份可使用只读模式。首次 `--read-only-data` 的部署，恢复前核对实际 `.env` 的 `DATA_ACCESS`，通过安装管理流程应用读写调整并验证挂载。

不复制主机 `.env` 或状态目录解决权限。默认容器不挂宿主 Docker socket；选择 Docker/systemd CPA 启停驱动前执行环境须具备相应权限，人工方式先真实停机再确认。

## 失败

恢复失败/中断保持保护态。修正路径、权限或数据后，在同一恢复流程重新明确 `RESTORE`；不靠重启或通用 `RESUME` 跳过保护。覆盖前回滚/失败补偿有回归测试，但多目标掉电原子事务不在保证范围，文件系统/设备持久性需目标验证。

角色交接使用[专门流程](failover-failback.md)，不把历史恢复与故障接管混用。
