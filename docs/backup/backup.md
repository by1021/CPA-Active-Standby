# 日常备份

## 数据与周期

| 数据 | 选择 | 注意 |
|---|---|---|
| 共享认证目录 | 目录 | 不包含备份状态或节点差异 |
| 共享配置 | 普通文件 | 不直接同步监听、代理或 Tunnel 凭据 |
| SQLite | SQLite 一致性备份 | `.backup`，不把在线 WAL 库当普通文件 |
| 其他数据库 | 应用导出的普通文件 | 本服务不替代数据库原生备份 |

两端标签/类型一致，路径各自映射。邀请把主机相对路径映射到备机数据父目录；缺失备机恢复目标不作为权威来源。普通文件在线采集为尽力一致，不保证跨文件事务。

初始可设主→备 `60` 秒、二次备份 `3600` 秒、每类保留 `120` 份。按数据量、磁盘及实际耗时调整，不把周期设得比作业耗时短。二次备份复制已收到的有效快照，不采集空待机目录；同机二次副本不等于离机灾备。

## 成功判定

主机「运行概览 → 立即备份」，等待作业最终完成：

1. 主机最近传输更新，无作业错误。
2. 备机历史出现同一快照 ID。
3. 备机点击校验成功。

主机本地快照成功但 SSH 传输失败时保留本地恢复点，作业仍明确失败。任务已提交、快照暂时可见都不等于作业结束。

## 暂停与失败

- 取消「启用定时任务」并保存，只停调度，不改角色。
- 「暂停并进入保护态」是角色保护；需明确 `RESUME`，不解除未完成恢复/交接。
- 两端时钟同步；同代次旧副本被拒，不按随机 ID 猜新旧。
- 角色冲突、损坏归档、传输失败不覆盖最近有效快照，先[诊断](troubleshooting.md)。

**收到备份不自动更新备 CPA 运行数据。** 故障使用[接管](failover-failback.md)，指定历史回滚使用[恢复](restore.md)。
