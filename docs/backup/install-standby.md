# 备机一键安装

## 主机生成命令

主机完成安装、保存备份项目，处于普通主机状态，定时任务停用。终端菜单选择「生成备机安装命令」，或网页「节点配置 → 一键添加备机」。

| 参数 | 含义 |
|---|---|
| 主机连接地址/端口 | 备机访问主机的专用 SSH 端点 |
| 备机连接地址/端口 | 主机访问备机的专用 SSH 端点 |
| 备机本地 SSH 监听地址 | 备机可绑定、双方可达的地址 |
| 备机数据父目录 | 本机恢复目标的父目录，与源码/状态独立 |
| 部署方式 | Docker 或 Linux 本地，可与主机不同 |
| 备机配置目录 | 可选，自定义后后续管理保持同一目录 |
| 邀请有效期 | 默认 1800 秒，范围 60～86400 秒 |
| 首备成功后启用调度 | 默认开启；首备失败不启用 |

预览继承的是**已保存**主机数据标签、类型、相对路径与策略。确认地址、目录及完整安装计划后生成命令。

也可从主机命令行显式生成；`HOST` 按参数位置替换为对应主机/备机地址，`PORT` 为专用 SSH 端口，`TARGET` 为备机数据父目录：

```bash
bash start.sh generate-backup-command \
  --primary-host HOST --primary-port PORT \
  --backup-host HOST --backup-port PORT --backup-bind-host HOST \
  --backup-data-dir TARGET --backup-deployment docker --ttl 1800 --yes
```

备机自定义配置目录加 `--backup-output TARGET`；主机当前自定义部署加 `--output TARGET`。默认首备成功后启用调度，明确不启用加 `--no-auto-enable`。两种 `TARGET` 按各自含义分别替换。

## 备机执行

把完整命令交给指定备机管理员，在备机终端执行。无需先下载仓库、手工复制公钥或录入指纹。

GitHub 来源主机的引导器从 GitHub 获取邀请中的固定提交，重建源码白名单安装包；核对主机给出的版本、SHA-256 摘要、归档边界与逐文件清单后安装。下载或摘要不符停止，不回退其他来源。依赖经 apt-get/dnf/yum 从现有软件源安装，Docker 构建基础镜像来自镜像仓库；不将系统软件包或镜像存放在项目 GitHub 仓库。

直接由本地源码安装、没有 GitHub 来源信息的旧主机继续经严格 hostkey 校验的 SSH 提供固定摘要安装包。两种下载路径使用相同配对、首备及续装协议：

```text
独立备机身份 → 本地路径映射 → 公钥与服务器 hostkey 登记
             → 双向验证 → 首份备份接收/校验 → 按选项启用调度
```

只安装备份服务，不安装 CPA 业务、不写备 CPA 运行数据、不修改 Cloudflare 或防火墙。依赖从现有软件源安装；Docker daemon、systemd、sudo 和网络需按部署方式就绪。

## 完成与续装

- 双端身份/连接验证通过，首备作业最终成功。
- 备机出现与主机一致的快照 ID 并校验通过。
- 选择启用调度时，两端保存启用状态；否则仍停用。
- 主机网页邀请记录显示完成及快照 ID，备机在「备份历史」核对。

“已安装”“已认领”“已配对”均不等于首备成功。失败按[诊断](troubleshooting.md)修正，在邀请有效期内使用原命令/身份续装；重跑不换节点 ID、管理员令牌或永久密钥。异节点认领或原配对/数据配置冲突会停止，不静默替换。

已完成后再执行同一命令，只返回原首备收据，保留管理员后续暂停、停止服务和数据配置，不重新安装或启用调度。收据不是当前运行状态检查；确认服务请执行 `bash start.sh status --output TARGET`，`TARGET` 替换为备机实际配置目录，重新启动仍走管理菜单。

临时安装凭据默认 30 分钟有效，过期或撤销停止新的安装/配对。已完成首备验证并进入最终提交的交接由绑定永久身份续办，避免已验证结果因响应丢失而回退。完成后不再保留临时安装权限。

## 撤销与秘密保管

主机网页刷新邀请，在对应行核对 ID 和备机地址后撤销。最终提交中和已完成的记录不提供撤销；撤销不删除已安装服务、身份或有效备份。

页面关闭/退出登录清除本地命令，不等于撤销服务端邀请。命令含临时私钥，仅允许本次安装；主机永久私钥和管理员令牌不在命令中。不要把命令发到公开聊天、工单或普通日志。
