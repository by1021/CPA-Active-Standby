# 故障接管与回切

**先保护数据，再切业务入口；主恢复先备→主回灌，再回切。** Worker 不等待恢复，自动回主可能把请求送到旧主，操作前安排入口隔离。

## 主机故障：备机接管

| 顺序 | 在哪里 | 操作 |
|---|---|---|
| 1 | 旧主及入口 | 确认停止/隔离，处理自动重启、后台刷新及直连写入 |
| 2 | 备机 | 停止备 CPA 全部写入，核对最新有效主副本和本机恢复目标 |
| 3 | 备机页面 | 「备机确认接管」，选择快照、预览、勾选隔离/停写，输入 `PROMOTE` |
| 4 | 备机 | 等待最终成功，启动/核对 CPA 并执行真实请求 |
| 5 | Cloudflare | 按[配置手册](../cloudflare/README.md)确认入口流向备机 |

网络不可达不证明旧主停写。接管后备机为数据权威，拒绝迟到旧主副本；不要重新启用旧主→备备份。

## 主机恢复：最终回灌

1. 备机继续服务，主 CPA 与入口保持隔离。
2. 主机「主机准备恢复」，确认停写，输入 `RECOVER`。
3. 安排交接窗口，排空备机在途请求，停止全部写入/后台刷新。
4. 主机「主机执行回灌」，确认两端停写，输入 `FAILBACK`。
5. 等待备机最终副本、主恢复/校验与角色交接完成；核对新增、修改及删除。
6. 主 CPA 启动及真实调用通过后，在 Cloudflare 回切入口。
7. 确认备机待命，恢复主→备正常调度。

回灌失败保持保护态，同一交接流程重试，不盲目启动旧 OAuth 数据，不用历史 `RESTORE` 冒充角色交接完成。

默认 CPA 人工启停；备份容器没有宿主 Docker socket/systemd 权限，驱动选择不等于执行能力已具备。确认框是管理员对真实停写/隔离的承诺，不是自动隔离证明。

CPA 版本、挂载/UID、OAuth 刷新、SSE 排空和入口传播须目标环境演练。本服务是明确确认的单写角色，不是网络分区自动仲裁。
