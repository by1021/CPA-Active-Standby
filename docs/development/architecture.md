# Linux 原生命令架构

## 组件

| 层 | 原生命令／文件 | 责任 |
|---|---|---|
| 管理页面 | `www/`、nginx | 中文配置、状态、历史和危险动作确认 |
| API入口 | `cgi/api.cgi`、fcgiwrap | 管理员Bearer认证、限长JSON、固定路由 |
| 任务／角色 | `bin/cpa-dr`、`lib/service.sh`、flock、jq | 跨进程互斥、持久角色、作业结果、调度 |
| 数据核心 | `lib/common.sh`、`lib/snapshots.sh` | 配置边界、SHA校验、回滚和补偿 |
| 快照／恢复 | tar、sha256sum、rsync、sqlite3 | 文件/目录/SQLite备份、确认后原位恢复 |
| 跨机 | ssh、`lib/transport.sh`、`bin/cpa-dr-ssh-dispatch`、`bin/cpa-dr-rpc` | 固定RPC白名单、严格known_hosts、归档流 |
| 部署 | `scripts/install/`、`scripts/runtime/`、`deploy/` | 原生依赖、systemd timer和可选Web服务 |
| 一键安装 | `lib/enrollment.sh`、`bin/cpa-dr-enroll-rpc`、`scripts/packaging/` | 一次性邀请、固定安装包、当前目录项目/稳定入口、独立身份、首备验证 |

Cloudflare不参与备份协议，CPA业务端口不充当备份管理接口。运行后端没有Python/Node服务；JavaScript只运行在浏览器，可选页面测试使用Node。

Nginx显式生成固定FastCGI参数，保留外部Host端口，Host/Origin/Authorization各传一次，不依赖发行版默认参数对Host的改写。CGI对浏览器管理请求继续严格核对Origin，不开放跨域管理。

## 数据与互斥

配置是JSON，由jq读取和验证，不作为Shell代码执行。稳定数据标签连接两端各自路径；原始归档路径仅审计。状态与历史库独立于允许的数据父目录，秘密只保存在本机受限文件中。

快照包含来源身份、主/备固定角色、代次、用途、纳秒UTC时间、文件大小/SHA和空目录；历史排序兼容旧秒精度。暂存校验后发布；高频状态写用GNU `sync FILE`同步指定文件及父目录，完整数据树用一次`sync -f`确保子文件落盘，避免每次状态写都刷新整个文件系统。校验失败不覆盖有效恢复点。恢复采用本机标签目标、原位rsync和覆盖前回滚，保留既有挂载inode及本机所有权。普通在线文件不承诺跨文件事务；SQLite由sqlite3 `.backup`生成一致副本。

数据/角色写操作共用operation.lock（flock）；邀请有自己的原子持久状态和身份限制，跨机等待不持有本机数据锁。CGI、CLI、调度与SSH的数据写者使用同一数据锁；control.lock让等待中的控制请求优先于后续tick。管理操作超时返回HTTP 409，表示未接纳、没有创建新任务，等当前写者完成后可重试。长任务有独立ID及持久结果，不因页面断开消失；快照可见不代表作业已经全部完成。保护态不通过普通重启解除。底层sync/文件系统/设备兑现持久性，未承诺多个数据目标的掉电原子事务。

## SSH与角色交接

SSH固定私钥、BatchMode和StrictHostKeyChecking；自动安装邀请固定主机hostkey并登记备机持久hostkey，手工维护则在可信控制台核对后登记known_hosts。双方同端点已有不同hostkey时拒绝替换；备机在已有部署安装前只读核对实际known_hosts，写入前再次核对。双方使用OpenSSH端点查找支持明文、hashed、别名、注释及大小写端点，逐候选核对算法和公钥内容；匹配记录全部必须是相同普通公钥，不接受冲突多候选或撤销/证书标记。相同pin保留原文件及格式、不重复写入，可信缺失才新增。对端authorized_keys使用restrict + 强制RPC，仅允许状态、备份收发和受控交接，不开放任意命令或端口转发。RPC参数白名单解析，不使用eval。

同代次副本按有效UTC创建时间比较，只接受明确更新的版本；旧秒精度同秒不同ID顺序不明时拒绝，不按随机ID猜顺序。重复当前同ID仍须验证；已提交交接重复确认只返回原确认，不回退最新副本。历史恢复保持CPA停机，待机节点不因RESTORE成为第二写者；回灌启动失败记录尝试与成功两种状态，重试保留已恢复数据，但必须成功启动后才能提交交接。

来源硬链接采集为独立快照文件；恢复目标树中的普通文件必须链接计数为1。整批预览、每项实际写入及失败补偿均复查，防止`rsync --inplace`改写其他路径的同inode文件。

独立历史恢复在作业接纳时原子保存角色/阶段/代次上下文并进入保护态；失败或中断只允许明确确认的同流程`RESTORE`重试，禁止通用`RESUME`和跨接管/回灌流程覆盖。恢复成功的调度阶段与作业完成原子发布，CPA不自动启动；已提交交接历史不当作进行中交接，旧无可信上下文失败状态不推断权威角色。

对端写请求允许等待本机锁60秒；管理操作等待5秒，tick不等待。超过等待/传输上限会保留有效快照并报错，不以并发覆盖换取吞吐。

主正常：primary_active采集，backup_standby接收并做二次副本。备接管：管理员确认旧主隔离/备CPA停写，恢复主有效副本后backup_active，拒绝旧主上传。主恢复：先primary_recovering禁主→备，备停写生成最终副本、主回灌，再同步新的主来源基线并提交交接，之后备待命。失败保留保护态，不盲目启动旧OAuth凭据。

这里是明确确认的单写角色，不是自动网络分区仲裁。二次快照仍在本机故障域；静态加密与离机备份由部署方安排。

## 部署与源码依据

宿主机由systemd timer触发tick，配置秒级周期由tick动态判断。Docker内用原生进程和Shell循环调用相同逻辑；默认不挂宿主Docker socket。Web权限、允许数据根、SSH公钥/hostkey文件由部署配置限制。

当前协议依据交付源码：[配置](../../cpa-dr/lib/common.sh)、[快照](../../cpa-dr/lib/snapshots.sh)、[服务](../../cpa-dr/lib/service.sh)、[CLI](../../cpa-dr/bin/cpa-dr)、[CGI](../../cpa-dr/cgi/api.cgi)、[Compose](../../cpa-dr/deploy/compose.yaml)。真实systemd安装、CPA启停/UID、OAuth、长连接及入口隔离须在部署环境验收。

## 一次性安装邀请

主机生成绑定主节点、两端端点、部署方式、备机路径映射、策略和安装包摘要的邀请，默认1800秒（60～86400秒）。安装包来自源码白名单，不包含测试、文档、运行状态、密钥或业务数据。引导命令只带临时身份，主机永久私钥与管理员令牌不导出。备机独立初始化身份，重复执行按原身份续装。

邀请与续装沿用配置中的`peer.identity_file`和`peer.known_hosts_file`，不硬编码默认传输文件。永久公钥从实际私钥派生；要求可读取、无需口令的Ed25519私钥，存在的`.pub`必须匹配，缺失`.pub`允许。主机在生成临时身份/安装包前预检实际传输文件；备机在安装前预检，并使用同一实际私钥注册和连接。已运行Docker在容器中读取实际路径；停止Docker只从已核验的`/state`挂载映射读取，其他路径提前停止，不为读取秘密启动服务或辅助容器。已确认的历史收据完全只读，不依赖当前传输文件可用。

专用SSH全局强制dispatcher，`ExposeAuthInfo=yes`的`SSH_USER_AUTH`提供实际认证公钥，临时身份与永久身份走不同固定操作白名单。缺失/未知认证信息拒绝，不因为删除全局强制命令而开放Shell。临时身份仅能操作绑定邀请；最终确认由注册备机永久身份证明。依据本机官方`sshd_config(5)`与`ssh(1)`，实际行为须真实SSH验证。

邀请记录在实际状态目录的`enrollment/invites/`，并发认领由持久记录/锁控制。主机先只读预检对端hostkey，再保存唯一备机认领身份；所有已持久化认领（包括撤销/完成记录）约束同一节点、公钥及hostkey。端点维护仍可沿用同一永久身份，失败只能由该身份续办；known_hosts与配置绑定成功后才授权永久RPC，避免部分失败留下未绑定权限。内部状态issued→registered→committing→completed，页面将issued显示为待安装并保留撤销入口；撤销/过期阻止新的安装及配对，已进入最终提交可由绑定永久身份续办。每个邀请的completion.lock隔离完成流程，operation.lock仅保护本机数据/角色临界区，不持锁跨机等待双向回调。双方双向测试、主机首备完成、备机同一有效快照校验成功后才按选项启用调度，并从该时刻开始计算下一周期，避免首备后立即重复采集。失败保留身份和阶段，不假报已完成、不写CPA工作目录。

备机激活与主机最终提交是两个步骤；安装器只有验证主机返回的邀请ID/首备ID及completed收据后，才保存`completion_acknowledged=true`。备机已激活但没有最终收据时，原命令只使用永久身份续办主机提交，不重新安装；只有确认过最终收据的重跑才直接只读返回。

新备机项目位于首次执行邀请时的`pwd -P/cpa-dr`，固定源码在项目`releases/版本标识/cpa-dr`，与配置、状态及业务数据分离；Docker默认配置在项目`config`，Linux本地或邀请明确的配置目录以实际记录为准。邀请私密进度继续由执行用户`$HOME/.local/share/cpa-dr/enrollment/邀请ID`保存，并记录原项目位置，以便换PWD重跑仍复用原安装。旧隐藏`sources/邀请ID/cpa-dr`及配置保持兼容，不强制迁移。安装包的摘要、版本及逐文件清单在解包前后分别校验，兼容部署文件在安装包/安装目录中实体化。已完成邀请的原命令复用校验过的源码并只读返回原首备结果，不再次请求已撤销的临时权限、不重新安装/重启、不改管理员后续暂停或数据配置；未完成流程遇到不同邀请、节点、数据映射或容灾保护状态，在安装写入之前拒绝。引导父进程保留安装锁，启动的服务不继承该锁。加入前先核验完整部署发现结果；只有明确未安装且无异常原因的空记录才允许首次安装。损坏、链接、不可读或旧式待确认记录及查询工具缺失均在数据目录/安装写入前拒绝，不把空记录当作可信不存在。

管理API新增`GET/POST /api/enrollment`、`POST /api/enrollment/revoke`，全部保留管理员Bearer及同源校验。创建仅向页面输出邀请ID、有效期与明确请求的安装命令，CLI额外的原始邀请/临时私钥字段被投影去除；列表只含非秘密状态。页面使用独立邀请表单，退出登录/关闭对话框清除命令，异步返回按会话隔离，避免登出后重新显示秘密。

## 结构与兼容

用户手册在`docs/backup/`，Cloudflare配置说明在`docs/cloudflare/`，历史方案在`docs/archive/`，工程资料在`docs/development/`。根`start.sh`转到保留的服务入口，旧脚本/部署/测试命令由兼容入口继续工作。源码分类不迁移既有`.env`、安装记录、状态根、快照格式或密钥。Docker/native管理和专用SSH监听分开，监听调整核对原记录，不修改防火墙或Cloudflare。

新邀请、首备、权限与续装的本机证据见[验证记录](verification.md)；历史测试证明只绑定旧源码树，不自动视为此版本通过。真实宿主systemd/发行版安装、CPA行为与入口仍需目标环境演练。

## GitHub 固定版本安装

根 `install.sh` 首次安装经 GitHub commits API 解析完整 SHA，再获取同提交下载器；下载器仅通过 HTTPS 访问固定 codeload URL，按精确成员白名单解包，拒绝链接/特殊文件、重复及越界路径。兼容部署链接不直接解包，而从 `deploy/` 实体化公共模板。源码归档重建为确定性安装包；目录、可执行入口与公共文件权限规范化，不受 Docker/native chmod 或解包 umask 影响，逐文件清单及摘要由既有校验器检查。

新主机项目根为安装命令首次捕获的`pwd -P/cpa-dr`，`--install-dir`可显式指定；新配置默认项目`config`，`--output`独立控制配置。源码为项目`releases/<SHA>/cpa-dr`，Docker状态在配置`state-native`，Native服务/状态默认路径不变。项目`start.sh`与执行目录快捷`start.sh`关联受限`install.json`（format_version、project_dir、source_root、config_dir、deployment、install_id，备机可包含invite_id）；文件是数据，不source/eval，需验证归属、路径、权限及部署身份。安装记录及配置/状态不纳入不可变源码清单。入口按自身位置定位，跨PWD仍管理同一部署。目标顺序为显式`--output`、入口关联、源码自带部署、已知旧配置；保留同源码Docker/native的原歧义选择，旧配置不抢占源码自带目标。已知目录或记录的链接、权限、格式异常明确报未知/异常，不跳过后误报未安装。

项目标记与锁须为单链接且归属/权限可信的普通文件；标记核对内容、原子创建，项目锁非截断打开，避免别名文件被覆盖。已固定/打包源码的清单必须存在并通过核验，删除、悬空链接或内容异常均不执行源码；关联记录用可选布尔 `manifest_required` 保存登记时的要求，旧 v1 记录按固定安装布局/来源补判。可信本地无清单源码及 commit:null 本地模板保持兼容，异常来源记录不冒充本地源码。首次安装、旧接管及备机登记集中输出项目、配置、源码和安装记录中的实际状态目录，不由新布局猜测状态位置。

已知 HOME 部署路径逐级检查祖先可遍历性，不因 `-e` 遇权限拒绝而当作目录不存在。公共引导器在解析 SHA、下载辅助文件前检查；直接下载器在依赖安装前独立检查，未关联候选异常均不建立第二份部署。已有稳定关联优先于 HOME 扫描；稳定入口自身携带关联与源码校验，不依赖旧源码存在新版 helper。同关联 Native 写操作经确认后 sudo 回稳定入口，root 核对捕获的源码、配置、后端、install_id 与物理执行目录，再委派原源码；显式同配置不能跳过身份核对，真正不同 `--output` 仍优先。固定 release 源码入口同样核对关联并保留此重入路径；邀请加入在解析实际目标后、提权及副作用前核对。root 原子更新入口/清除收据保留原拥有者。清除收据的默认读取仅在 Native/Docker JSON 与旧 `.env` 都确实缺失、祖先路径可信且可遍历时免身份对照；现存或未知记录不因此跳过。清除后安装产生新 ID 时，收尾登记先核验新部署及清单，再以内部记录读取约束同源码/配置和清除收据更新入口；非清除的异 ID 仍拒绝，写操作入口的严格预检不变。只读 status/doctor/logs 不自动提权，选项在动作前后含义一致；非终端写操作没有 `--yes` 时在 sudo 前停止。源码自带 Docker 配置不覆盖显式 Native 后端选择，仍保留原 `/etc/cpa-dr-native` 选择与显式 `--output` 的最高优先级。

旧GitHub主机的隐藏源码和配置不强制搬迁；引导器核验已有记录后仅注册稳定管理入口，默认重跑不追踪main、不下载/重新安装、不重置身份。旧部署源码不含新管理辅助脚本时，稳定入口仍显式传原配置目录给旧入口；不注入旧源码而破坏原邀请摘要。首次交互主机安装后连续衔接可取消的备机向导，非交互只有`--generate-backup`明确要求才生成。SSH回环监听的调整单独确认，管理监听/防火墙不联动。安装成功与邀请生成失败独立报告，调度仍由原首备确认协议决定。

`scripts/packaging/github-source.json` 记录仓库及固定提交，经源码打包、Docker COPY 和 native 安装一并保留。生成邀请时安装包摘要附带来源信息；备机引导命令内嵌同一下载器，从 GitHub 取得同提交并重建安装包，要求版本和摘要与主机完全一致，再进入原 SSH 加入协议。源码有本地修改会使摘要不符并停止。旧本地源码的 commit 为 null 或无来源文件时，继续使用原 SSH 固定安装包。已完成邀请优先复用持久源码，不重新下载或使用撤销的临时权限。

系统依赖来自发行版现有软件源，Docker 基础镜像来自镜像仓库；GitHub 仅承载服务源码与公共配置模板。GitHub API 限速、代理、CA、软件源及真实宿主 systemd 的可用性仍须部署环境核对。
