# 可发现安装与连续配对需求

status: final

## 原始动机与确认范围

用户反馈 GitHub 安装落在隐藏 SHA 目录，执行目录没有 start.sh；自行找到源码后管理入口丢失 --output，误报未安装。用户确认优化方案并要求修改及验证。

安装到命令执行时的当前目录下 cpa-dr，保留固定、可直接调用的管理入口；已有部署可自动关联；主机首次交互安装后直接衔接备机邀请向导。源码、配置、状态分离。旧部署、Docker/native、固定提交/摘要、SSH 配对及同身份续装保留。

## 用户视角验收

- 在 /root 或其他目录执行一键安装，项目落在该目录的 cpa-dr，而非强制隐藏 HOME 路径。
- 安装后在同一目录 bash start.sh 即可管理，进入 cpa-dr 后也可直接管理；从其他目录用完整入口仍找到同一部署。
- 日常操作无需再次填写 --output；显式 --output 优先，多份部署不猜测，不可读/损坏不报未安装。
- 首次主机交互安装末尾可直接填写备机参数并生成命令；非交互不等待输入。
- 备机在其命令执行目录安装，保留版本一致、自动配对、首备、同身份续装。
- 重跑及旧部署接管不重置管理员令牌、公钥、配置、快照或 Compose 项目身份。
- 输出集中说明项目、配置、状态和完整命令，区分服务运行、配对与调度。

## 范围与取舍

不安装/启停 CPA 业务，不修改 Cloudflare、防火墙、系统软件源或现有账户。Native 服务/状态默认位置不改；稳定入口记录其实际位置。已有配置与状态不强制搬迁。首次下载继续固定提交，重跑已有安装不自动追踪 main 或升级服务。其他 start.sh 不覆盖。
