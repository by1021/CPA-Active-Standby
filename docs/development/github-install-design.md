# GitHub 一键安装交付

## 需求与范围

同步当前工作区至 GitHub，提供无需预先克隆仓库的主机安装命令；主机生成的备机命令继承地址、数据项目与策略，并从 GitHub 获取相同版本的服务文件。整理正式 README。保留已有部署、SSH 邀请、配对、首备与续装协议，不安装或启停 CPA 业务，不修改 Cloudflare。

## 实现约定

单安装模块 Feature；主线程实现。仓库未初始化 Athena 状态，沿用无状态工作方式，不新建 `.ai_state`。使用公开 GitHub HTTPS 接口解析提交 SHA，再下载固定提交的源码归档。仅提取服务白名单目录及必要入口，拒绝链接、特殊文件、重复及越界路径；重建确定性安装包并校验逐文件清单。安装源信息随 `scripts/packaging/github-source.json` 进入 Docker/native，用于新备机邀请。既有本地源码部署继续使用固定摘要 SSH 安装包，兼容原命令。

- AC1: 根 `install.sh` 可从 GitHub 获取固定提交并进入主机安装；参数原样传递，默认配置与源码分离，下载失败不启动安装。
- AC2: GitHub 来源主机的备机邀请固定 repository/commit，备机从 GitHub 获取同版文件，版本及摘要不符停止，不回退其他来源；原 SSH 配对和首备校验保留。
- AC3: 已完成邀请复用校验过的源码，不再次下载或更换身份；本地源码邀请保持兼容。
- AC4: 自动化测试覆盖下载失败、归档边界、固定提交、参数传递、持久源码损坏拒绝、GitHub 备机首装及精确重跑；README 命令与实现一致，本地文档链接有效。
- AC5: 不上传运行数据、令牌、私钥或临时验证输出；现有工作区整理完整提交，推送后远端 main 与本地一致。

## 交付切片

1. GitHub 安装入口及备机获取来源（AC1–AC3）。
2. 正式安装文档与 GitHub 同步（AC4–AC5），依赖切片 1 的实际行为。

## 验证

下载 HTTP fixture 与失效输入测试；既有邀请、部署、管理、API/页面回归；隔离容器中的真实 SSH 与首份备份；全量 Shell 语法、ShellCheck 与文档链接。发布后实测 GitHub raw/codeload 下载，不在真实主备服务器安装。使用 `athena run`，无活动 sprint 的输出不称为正式门禁证据；独立 reviewer 审查冻结差异及日志。
