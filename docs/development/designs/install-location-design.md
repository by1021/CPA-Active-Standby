## 当前 / 期望 / 不变行为

当前：github.sh 将源码与配置写入 HOME 隐藏路径；管理默认查 ROOT，遗漏原配置；安装最后仅打印无路径的邀请生成命令。
期望：安装到捕获的 PWD/cpa-dr，生成稳定入口与 JSON 部署关联，所有操作使用同一部署；首次主机安装末尾衔接邀请向导。
不变：安装源码仍固定 SHA、校验摘要/清单、拒绝链接/越界；私钥不进源码包；数据隔离、安装身份、作业锁、已有配置保护、SSH 配对/首备/续装保持。

## 实现决策

- 项目根默认 pwd -P/cpa-dr，--install-dir 只控制项目根，--output 仍只控制配置。入口捕获目录早于下载/提权/内部 cd。
- 项目 start.sh 稳定指向 install.json 中的源码与配置。源码放 releases/<commit>/cpa-dr（非 GitHub 来源可用固定版本摘要），配置 config，Docker 状态留在配置内或独立 state；不为布局强行移动现有路径。
- 当前目录 start.sh 是快捷入口，仅不存在或验证为本项目入口时写入，其他文件保留并提示完整项目入口。入口以自身路径定位，JSON 只作为数据，禁止 source/eval。
- install.json 关联项目、source_root、config_dir、部署身份；校验普通文件、绝对路径、拥有者/权限、来源与有效部署记录，写入原子化；无全盘扫描。
- 目标优先级为显式 --output、入口关联、源码自带部署、已知旧部署。多个有效候选明确选择/报歧义。源码入口也能发现属于自己的已有 GitHub 配置。
- 旧部署接管先校验来源与安装身份，仅注册入口，不移动状态、不隐式重新安装或追 main；后续升级必须明确操作。
- 备机 bootstrap 在执行目录建立相同稳定项目根；旧邀请/已完成续装仍能使用已有持久源与进度，不能因为换 PWD 重新配对或下载。
- 首次主机交互成功后询问生成邀请，默认继续；复用现有 cpa_generate_invitation，不自动提交未确认计划。参数齐全且显式要求时支持非交互生成。取消/邀请失败区分安装成功，不重置或启用调度。
- 展示 installed/running/paired/enabled 四个维度、项目/源码/配置/状态、可复制完整入口。检查 SSH 回环监听，确认后才修改专用 SSH，管理页面保持原监听。

## 验收

- AC1: 首次 GitHub 主机与备机安装落在执行目录 cpa-dr；--install-dir 与 --output 可独立指定；固定提交及清单校验保持。
- AC2: 当前目录及项目目录 start.sh、跨目录完整入口，menu/status/doctor/logs/start/stop/restart/generate-backup-command 自动定位同一部署；显式 --output 优先。
- AC3: GitHub 隐藏旧部署与自定义配置可接管；重跑不重置身份、配置、备份或项目名；默认不升级；其他 start.sh 不覆盖。
- AC4: 多份候选、损坏/权限不足/链接入口记录不误报未安装、不执行安装/删除或选择不明目标；新入口不削弱原作业锁与归属检查。
- AC5: 首次主机交互完成后直接进入可取消邀请向导，明确主备端点与 SSH 监听；非交互不挂起，显式生成参数通过已有确认语义生成。
- AC6: 备机固定同版本、真实 SSH 配对/首备、已完成邀请换目录重跑不重新下载/重启/改身份；旧 SSH 来源与 GitHub 来源均兼容。
- AC7: Docker/native 输出包括实际路径和完整管理命令；状态区分已安装/停止/未知，菜单不暴露令牌；自动与手工配对文案分开。
- AC8: 新行为先红后绿；安装、管理、依赖、协议、核心、API/页面、静态回归及隔离真实 Docker/native 链路通过，真实 systemd 模拟边界明确。
- AC9: README/主备安装/排错/架构文档同步，验证与独立审查记录说明实际结果和未验证环境。
