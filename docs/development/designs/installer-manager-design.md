# 安装入口管理菜单

状态：定稿；2026-11-06，用户确认预览后实施。安装模块 Feature；不初始化 `.ai_state`，沿用项目普通 `athena run` 与独立审查记录，不宣称正式 sprint 门禁通过。

长期需求见 [安装入口需求](../requirements/installer-manager.md)。本设计替代旧设计中“无参数直接安装/重跑启动”和“确认后选择部署方式”的入口顺序；数据与卸载保护不变。

## 需求与范围

用户要求执行脚本先选安装、卸载、检测状态等操作，并先预览方案、确认后实现。已确认范围包含中文循环菜单、安装计划、两种部署的只读状态/诊断、服务启停/重启、日志和原有卸载清理保护。不改 CPA 业务、主备协议、配对、恢复算法、Cloudflare 或系统用户策略。没有升级/自动修复入口。

## 顺序切片

1. 只读状态、诊断与日志：单独命令可验收；不构建、初始化、安装依赖或启动临时容器。
2. 中文菜单与安装计划：调用原有生命周期，确认前无写入；完成或失败后刷新菜单。
3. 服务管理与回归：实际进程状态、归属校验、任务中断保护和本地/Docker验证。

## 实现约定

- 无参数 TTY 进入菜单；无参数非 TTY 报用法错误。显式 `menu --output DIR` 选择自定义安装；旧带参数安装及卸载命令兼容。
- 命令 `install/status/doctor/start/stop/restart/logs`。只读命令不自动 sudo，不读取/打印原始私钥/令牌；日志原文可能含业务秘密，展示前提示。
- 默认仅探测源码目录和 `/etc/cpa-dr-native`，多部署交互选择或用参数明确目标；不递归扫描文件系统。
- 记录状态与真实进程状态分开显示。旧 `.env`、损坏记录、缺工具、权限不足不等同于未安装。Docker 只读取已有容器；本地读取已有 JSON。未运行容器不创建临时实例。
- 管理页面 `/healthz`、认证 API 与 SSH 分开检查。状态中的对端字段为已有历史记录，不自动探测对端。诊断可检查本地端口/路径/依赖，不修改配置。
- 安装完整计划在依赖安装、sudo 和写入前确认；旧无人值守依赖齐全的安装行为保留。首次向导角色→数据→方式→完整确认，既有安装计划保留全部配置。
- 新服务管理必须验证目录/单元或容器标签与挂载归属。停止/重启/卸载取得服务任务锁，拒绝正在执行的任务；锁保留至服务停止完成。原停止失败及清理保护不变。
- 本地启动只启动已安装单元；卸载后恢复使用 `install`。Docker 启动已有容器，不构建或创建。停止不禁用已安装单元，重新开机行为沿用部署配置。

## 验收

- AC1: 无参数终端显示状态及六项菜单；选择、无效输入、返回、失败刷新和退出可复现；未安装项显示不可用，多部署不擅自操作。
- AC2: 状态/诊断识别记录与实际运行状态；管理页面、API、SSH分开；配置角色/调度/任务/最近备份与历史对端字段脱敏显示。无配置、锁、密钥、软件包、构建、容器创建或启动副作用；权限不足显示未知。
- AC3: 安装计划包含角色、来源、方式、目录、监听、依赖及权限，最终确认在依赖/sudo/写入前；取消无副作用。既有安装和旧参数命令不覆盖设置或秘密。
- AC4: 两种服务启停/重启及日志明确指定目标，只操作有归属证据的已安装服务；破坏性操作确认，忙碌/状态未知/锁被占用拒绝中断。停止失败不显示成功；已卸载恢复走 install。
- AC5: 卸载预览停止、删除与保留对象；清理须 PURGE 或显式 --yes；原始数据、源码、未知配置和无关服务保留。异常归属/路径、失败停止、运行任务不进入删除。
- AC6: 两份 README、帮助同步；新增菜单/状态/管理测试先红后绿，原入口、依赖、部署及本地/Docker隔离测试回归，ShellCheck/Bash语法通过；独立审查通过。真实宿主systemd未运行的边界标待验证。
