# SSH 安装邀请的权限与恢复边界

2026-11-08，配套[需求](../requirements/structure-enrollment.md)与[设计](structure-enrollment.md)。

## 决策

继续使用专用 OpenSSH 服务，全局强制 dispatcher，并启用 `ExposeAuthInfo`。从 sshd 提供的 `SSH_USER_AUTH` 文件读取实际认证公钥，区分临时邀请与永久备份身份；缺失、未知或畸形身份拒绝执行。保留普通 RPC 白名单，不开放 Shell、PTY、转发或密码登录。

临时邀请只允许指定安装包、认领及安装进度查询。完成配对使用备机新永久公钥证明身份；主机永久私钥和管理员令牌不进入命令。

包内容固定为服务源码白名单，hostkey 和摘要由主机邀请固定；备机在解包前检查成员路径、类型、重复项与清单。解包后的源码持久保存，与部署状态及业务数据独立，以支持相同命令续装。

认领在全局操作锁内保护唯一对端；跨机验证不持有数据操作锁。首次备份确认后进入可恢复的最终提交阶段：永久身份可以续办，临时凭据不因续办重新生效。完成后保留审计结果，关闭临时权限；重跑不重建身份，不重新启用管理员后来关闭的调度。

## 审议结果与取舍

只读架构审议指出旧原生安装升级、临时源码清理、多邀请抢占、跨机回包后状态重验及提交断点是重点验收。实现使用受归属/摘要保护的更新入口、持久进度、原子认领、端点/配置/角色代次重验与同身份恢复。

没有选择仅按 authorized_keys 每密钥 command 取消全局限制，避免旧授权行误开放普通命令；没有新增常驻 HTTPS 配对服务，避免额外监听和证书管理。

## 依据

- 本机 `sshd_config(5)`：`ExposeAuthInfo` 会记录认证方法及公钥，并通过 `SSH_USER_AUTH` 向会话提供文件位置。
- 本机 `ssh(1)`：`SSH_USER_AUTH` 为服务端可选提供的成功认证记录。
- 实现与运行证据见[本轮设计验收](structure-enrollment.md)及[验证记录](../verification.md)。文档核对不替代真实 SSH 测试；真实宿主 systemd/发行版/CPA 业务按部署环境另行验证。
