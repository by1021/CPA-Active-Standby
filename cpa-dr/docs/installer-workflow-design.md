# 安装向导与卸载清理

状态：定稿；2026-11-06。用户要求：运行 `start.sh` 后先选主机/备机，再选择或输入需要备份的数据，确认后选择 Linux 本地或 Docker 部署，并提供卸载清除命令。

这是安装模块的 Feature，不改备份、恢复、配对协议或页面。未启用 `.ai_state`，沿用项目现有的需求/设计、普通 `athena run` 与独立复审记录；不初始化状态库，不把普通检查称为正式 sprint 门禁。

## 顺序交付

| 切片 | 用户可观察的结果 | 依赖 |
|---|---|---|
| 安装向导 | 主备角色 → 多项数据 → 确认 → 本地/Docker；选择实际写入服务配置 | 无 |
| 卸载与清除 | 根据安装记录停止并移除本服务；显式清除专用状态和安装文件 | 安装记录 |

## 范围与取舍

- 无参数首次运行进入中文向导。数据父目录限制可备份路径；支持目录、普通文件及 SQLite 一致性备份，多项使用唯一标签，两端标签/类型需一致。备机可填写尚未存在的恢复目标。
- 非交互首次运行明确提供 `--role primary|backup`、`--data-dir TARGET`、`--deployment native|docker`；`--source 标签:类型:路径` 可重复，不指定时选择整个数据父目录。已有部署直接重跑，不重置页面配置、角色、令牌或 SSH 密钥；显式冲突参数报错。
- 选择部署方式后才检查/安装对应依赖；本地方式不要求 Docker。Linux 本地复用 systemd 安装器，普通用户经 sudo 安装，使用独立单元、端口和目录。Docker 复用现有初始化、Compose 健康等待及容器内 CLI。
- 安装选择通过原有 JSON 校验/CLI 写入，保持 `enabled=false`。不自动配对、不启用备份、不执行 CPA 启停或修改 Cloudflare。
- 安装记录含部署方式、项目名、路径及目录所有权标记，配置作为数据读取。安装失败保留配置与状态，可重跑或卸载；外部环境变量不覆盖文件配置。
- Docker 私有运行配置通过容器读取/合并，普通客户端不修改 root 创建文件的所有权；已停止服务的显式参数核对使用无调度/无发布端口的临时只读 CLI。Docker 清除 root 创建的私有备份目录时检查 sudo 权限后才停止服务。
- `uninstall` / `--uninstall` 停止并移除容器或 systemd 单元，保留配置、代码、令牌和备份；`--purge` 额外删除本服务的专用状态和本地安装文件。默认询问确认；清除输入 `PURGE`，无人值守须显式 `--yes`。
- 清理前检查所有权、路径交集、符号链接及 systemd 单元归属。始终保留原始数据和源码，不全局 prune、不卸载共用软件包、不删除无关容器/单元或未知配置文件。

## 验收

- AC1: 首次终端交互严格按角色、数据、数据确认、部署方式排序；支持多项目录/文件/SQLite及备机缺失目标。取消确认无配置/部署副作用。
- AC2: 两种方式实际持久化角色、标签、类型及对应路径，Docker 转换为 `/data` 路径，本地使用宿主路径；备份保持停用，健康通过后才输出成功和秘密。
- AC3: 本地只检查/安装原生依赖，Docker 保留现有软件源安装、daemon/Compose能力、私有权限和健康等待行为；普通用户本地安装使用 sudo，普通 Docker 用户可读取容器创建的私有配置并完成安装/重跑。
- AC4: 已有部署重跑保留配置、秘密、节点ID及页面修改；本地单元启动从持久状态恢复易失运行目录的所有权标记，重启后仍可重跑。显式冲突参数、非法/重叠来源、缺失主机来源和不独立的路径在部署前报错。失败保留状态，返回非零。
- AC5: 两种卸载停止并仅移除本服务；本地重启或卸载后运行目录丢失不阻断正常重装/再次卸载。清除需明确确认，删除范围与安装记录一致。原始数据、未知配置文件和无关服务保留；异常记录、符号链接、目录所有权不匹配或停止失败时不执行删除。
- AC6: 帮助和两份 README 给出交互、批量安装、重跑及卸载/清除命令；ShellCheck、逐文件 Bash语法、入口/依赖/部署回归与隔离运行验证通过。本地真实 systemd 启动未经验证的部分单独标注。

## 实现依据

运行配置与校验以 `lib/common.sh` 的 `cpa_config_validate` 和 `lib/service.sh` 的 `cpa_save_config` 为准，安装调用已有 CLI，不另建配置协议。容器启动后用 `compose exec -T` 完成尚未完成的引导配置，完成标记防止重跑覆盖页面配置。systemd 单元停止/禁用后才删除，重新加载管理器。

官方 CLI 依据：Docker Compose 的 `exec`、`up --wait --wait-timeout`、项目名与 `down`，以及 systemd 的 `stop`、`disable`、`daemon-reload`。具体参数在本机 CLI 帮助和隔离运行中复核；不把 mock 当作真实发行版软件包或 systemd 运行证据。

运行目录依据本机官方 `systemd.exec(5)` 的 `RuntimeDirectoryPreserve=`：即使设为 `yes`，位于 tmpfs 的 `/run` 仍在系统重启时清空。FastCGI 和 SSH 单元均用 `ExecStartPre=/usr/bin/install -m 0600` 从状态目录恢复相同安装ID，不移除卸载入口的所有权检查。
